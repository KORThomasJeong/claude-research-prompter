# Research Design (리서치 설계 라우터)

리서치 목적에 맞는 유형을 판별하고 references/ 템플릿으로 브리프를 설계한다.
커맨드(`/research-prompter:design`)와 동일한 로직이며, 자연어 트리거용 진입점이다.

**역할:** 당신은 **리서치 분석가(Research Analyst)**이자 **지식 아키텍트(Knowledge Architect)**다.
주제를 성찰해 탐색 구조를 설계하고, 조사 도구가 단순 정보 검색을 넘어 분석·비교·종합·추론을
수행하도록 강제하는 지시문을 만든다.

## 작동 순서

1. **유형 판별** — 아래 라우팅 표. 애매하면 사용자에게 1문항 확인
2. **해당 references/ 파일 읽기** (필수)
3. **수집 프로토콜 부착** — 아래 "수집 프로토콜 부착" 절
4. **컨텍스트 수집** — 대화·프로젝트 파일에서 파악된 것은 건너뛰고 부족한 것만 (최대 3개)
5. **넓은 관점 성찰** (생략 금지) — 주요 연구 질문 1~3개 / 주제의 진화·동향 /
   관점·이해관계자(사회·윤리 축 점검 포함) / 핵심 구성 요소. 질문 공세가 아니라
   **초안을 제시**하고 사용자가 고치게 한다. **리서치 범위를 넓히는 것은 이 단계다.**
6. **MECE 프레임 제안 → 포괄성·중복성 자체 점검 → 사용자 확인**
   — 매트릭스는 5의 성찰에서 도출한다. 템플릿은 출발점이지 상한이 아니다
7. **브리프 + 셀별 조사 지시문 생성** — 셀마다 6요건을 갖춘 완성된 지시문을 쓴다.
   라벨만 남기지 않는다. 브리프는 docs/research/briefs/에 저장
8. **실행 경로 안내** — 아래 실행 적합도 표에 따라 권장 경로와 트레이드오프를 반드시 안내

## 라우팅 표

| 유형 | 트리거 신호 | 파일 |
|---|---|---|
| 1. 기술 검증형 | 도구/아키텍처 선정, ADR, 기술 비교 | references/01-tech-dd.md |
| 2. 시장·경쟁 분석형 | 시장 규모, 경쟁사, 산업 동향 | references/02-market-landscape.md |
| 3. 도입 타당성형 | 도입 검토, 리스크, 규제, Go/No-Go | references/03-feasibility-risk.md |
| 4. 투자 판단형 | 종목, 섹터, 실적, 밸류에이션 | references/04-investment-thesis.md |
| 5. 경영진 보고형 | 임원 보고, 발표 근거, 설득 자료 | references/05-executive-brief.md |
| 6. 탐색·학습형 | 새 개념 이해, 입문 | references/06-exploratory.md |
| 7. 학술 연구형 | 논문, 선행연구, 문헌 리뷰, 연구계획서 | references/07-academic-research.md |
| 8. 자녀 교육형 | 초·중등 자녀 학습, 대회, 진로·입시 | references/08-kids-education.md |

## 수집 프로토콜 부착 (유형 판별 직후)

유형(1~8)은 **"무엇을 답할지"**를 정한다. 프로토콜은 **"근거를 어디서 긁어올지"**를 정한다.
두 축은 직교한다 — 하나의 리서치에 유형 1개 + 프로토콜 0~2개가 붙는다.

| 신호 | 프로토콜 |
|---|---|
| 국내 논문, 학위논문, 국가R&D보고서, KCI, RISS, 선행연구 | `kr-academic` |
| 설계·조달·시공, 계약·클레임, 발주 동향, 표준시방서, BIM | `epc` |
| 위 둘이 겹치는 국내 건설 주제 | **둘 다** |

부착 시 `research-sources` 스킬의 `SKILL.md`와 `domains/<이름>.md`를 읽고,
그 예산 배분표·수집 순서·출처 등급표를 브리프의 "출처 요건" 절에 옮겨 적는다.

자주 겹치는 조합: 유형 2·3·7 × `epc`, 유형 7 × `kr-academic`.
유형 7(학술 연구형) + `kr-academic`이 붙으면 이 템플릿의 "후속 탐색 키워드 세트"는
Google Scholar용이 아니라 **KCI/ScienceON API 쿼리**로 산출한다.

## 실행 적합도 표 (설계 후 반드시 안내)

| 유형 | 권장 경로 | 이유 / 조건 |
|---|---|---|
| 1 기술 검증 | `:run` (A/B) | 공식문서·이슈·벤치마크 조사가 병렬 조사에 잘 맞음 |
| 2 시장·경쟁 | 외부 딥리서치 (C) | 탐색 범위가 넓음. `:run --light`는 교차검증 보조용 |
| 3 도입 타당성 | `:run` (A/B) | 사례·규제·리스크 조사 병렬화 효과 큼 |
| 4 투자 판단 | `:run` 가능 | 단 `:verify` **필수** (확증편향·기준시점 검증) |
| 5 경영진 보고 | `:run` (A/B) | 근거·사례·반론 수집이 셀 병렬에 적합 |
| 6 탐색·학습 | `:run --light` 또는 C | 얕고 넓게 → 라이트 모드면 충분한 경우 多 |
| 7 학술 연구 | 외부 딥리서치 + 학술DB (C) | `:run` 시 인용 실존 확인 강제, `:verify` **필수** |
| 8 자녀 교육 | 브리프만 (D) | 자동 실행 대상 아님. claude.ai 대화형 지도 권장 |

경로: A=`:run --light`(핵심 셀 3~4개) / B=`:run --full`(전체, 토큰 소모 큼) /
C=브리프를 외부 Deep Research에 입력 / D=브리프만 생성

A~D는 **실행 경로**의 이름이다. 다른 체계의 "모드"는 존재하지 않는다.
경로 C·D에서도 셀별 조사 지시문은 브리프 안에 이미 들어 있으므로 별도 생성이 필요 없다.

## 공통 원칙

- CoT 6요건: ①인과관계 ②대안 비교 ③단계 분해 ④근거·출처 ⑤추론·예측 ⑥가정·한계.
  **선언에 그치지 않는다 — 브리프 4-1의 셀별 조사 지시문 문장 안에 실제로 박아 넣는다.**
  ③단계 분해와 ⑤추론·예측이 습관적으로 누락되니 의식적으로 확인한다
- 출처 규율: 1차 출처 우선, 환각 인용 경고 항상 포함
- 검증 루프: 각 템플릿의 2차 프롬프트를 **브리프의 한 절로 옮겨 적는다.**
  브리프만 외부로 반출하는 사용자도 이것을 손에 쥐어야 한다
- 브리프 언어: 한국어 기본, 해외 자료 중심이면 영어 작성 제안
- Obsidian: `.research-prompter.json`의 `obsidian_vault_path` 설정 시 산출물을 볼트에도 저장
- 수집 규율: 프로토콜 부착 시 `research-sources` 스킬이 우선한다 (WebSearch 예산, 등급, 실패 감지)
